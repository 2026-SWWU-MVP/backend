# 시연 가이드

시연 시나리오(설계서 12장) 1~7단계를 그대로 재현하는 방법입니다. 같은 흐름을 `DemoScenarioTest`가 자동으로 확인합니다.

---

## 1. 데모 데이터로 서버 실행

`demo` 프로필을 켜면 처음 한 번 데모 데이터를 만듭니다 (원장 계정이 이미 있으면 건너뜀).

```bash
# 리허설: LLM 비용 없이 (Mock LLM + H2)
SPRING_PROFILES_ACTIVE=h2,demo ./gradlew bootRun
```

```bash
# 실제 시연: PostgreSQL + 실제 LLM (.env에 LLM_PROVIDER=openai, LLM_MODEL, LLM_API_KEY)
SPRING_PROFILES_ACTIVE=demo ./gradlew bootRun
```

IntelliJ에서는 실행 설정의 Active profiles에 `h2,demo` 또는 `demo`를 넣습니다.

### 만들어지는 데이터

| 항목 | 내용 |
|---|---|
| 학원 | 파인로드영어 (BASIC, 로고 포함) |
| 원장 | `demo` / `1234` (김원장) |
| 강사 | `teacher1` / `1234` (이강사), `teacher2` / `1234` (박강사) |
| 워크스페이스 | 건대부고 1학년 (빈 상태 — 시연 3~7단계용), 압구정고 1학년 (완료), 현대고 2학년 (프로필 검토 중) |
| 시험범위 | 건대부고 1학년·압구정고 1학년 "교과서 2과" (지문 2개, Mock 응답과 맞는 지문) |
| 다른 학원 | 한빛영어학원, 원장 `hanbit` / `1234` (최원장) — 압구정고 1학년 기출 1회분 |
| 학교 | 서울 고등학교 23곳 (`seed/schools.json`, 학교 테이블이 비어 있을 때만) |

### 더미 데이터 (화면 개발·시연용, #62)

LLM 호출 없이 모든 화면에 데이터가 보이도록 엔티티를 직접 만듭니다 (`DemoSampleData`). 기출 지문·문항은 시연용으로 새로 쓴 글입니다.

| 워크스페이스 | 상태 | 들어 있는 것 |
|---|---|---|
| 압구정고 1학년 | 끝까지 진행됨 | 추출 완료 기출 3회분 (2024-1 중간, 2024-2 기말, 2025-1 중간)<br>출제 프로필 v1(대체됨) → v2(강사 의견 반영, **확정**)<br>생성 작업 2개 (8문항: 채택 5 · 폐기 2 · 확인 필요 1, 수정 1)<br>시험지 "압구정고1 2과 서술형 대비" (4문항, 지문 2개)<br>학교 경향: 학교 DB 4회분 · 학원 2곳 |
| 현대고 2학년 | 프로필 검토 중 | 추출 완료 기출 1회분 + 프로필 v1 **초안** |
| 건대부고 1학년 | 빈 상태 | 시험범위만 있음 (시연 3단계부터 직접 진행) |

- 압구정고 1학년은 확정 프로필이 있어 기출·프로필 화면 없이도 **바로 문제 생성 → 검수 → 시험지**를 테스트할 수 있습니다.
- 데이터를 바꾼 뒤 처음 상태로 돌리려면 아래 "3. 데이터 초기화"를 따릅니다. 이미 데모 데이터가 있는 DB에는 새 더미 데이터가 추가되지 않습니다.

비밀번호는 시연용 값입니다. 실제 서비스 계정에 쓰지 마세요.

**기출 PDF는 저작권 때문에 저장소에 없습니다.** 시연 3단계에서 직접 올립니다 (로컬의 `experiments/exams/`에 있는 기출을 쓰면 됩니다).

## 2. 시연 순서

| 단계 | 누가 | 화면 / API | 확인할 것 |
|---|---|---|---|
| 1 | 원장 `demo` | 학원 정보·로고 → 초대 코드 발급 (`POST /api/academy/invites`) | 로고, 강사 2명 / 최대 3명, 6자리 코드 |
| 2 | 새 강사 | 회원가입 → 초대 코드 입력 (`POST /api/academies/join`) | 역할이 강사로 바뀜 |
| 3 | 새 강사 | 건대부고 1학년 → 기출 업로드 → 분석 → 출제 프로필 생성 | 문항 추출 결과, 통계, [기출] 규칙과 근거 문항 |
| 4 | 새 강사 | 강사 의견 "이번엔 어구 배열 위주로 낸다고 함" → 변경점 → 확정 | `changeSummary`, 지문당 구성 어구 배열 증가 |
| 5 | 새 강사 | 교과서 2과 지문으로 문제 생성 → 검수(채택) | 진행률, 어구 배열 비중 증가, 검증 상태 |
| 6 | 새 강사 | 시험지 만들기 → 문제지·정답지 PDF | 머리글 로고, 지문별 번호, 정답지 정답·해설 |
| 7 | `teacher1` | 로그인 → 같은 워크스페이스 | 확정 프로필·시험지가 공유됨, 작성자 표시 |

추가로 보여주면 좋은 것:
- 학교 DB: 다른 학원 계정으로 같은 학교 기출을 올려 두면, 기출이 없는 학원도 학교 경향으로 프로필을 만들 수 있습니다 (`GET /api/workspaces/{id}/school-trends`)
- 데이터 격리: 다른 학원 계정으로 이 학원의 워크스페이스 ID를 요청하면 404

### 실제 LLM으로 시연할 때 걸리는 시간

| 단계 | 시간 |
|---|---|
| 기출 분석 (텍스트 PDF 기준) | 약 1분 |
| 출제 프로필 생성 | 약 10초 |
| 강사 의견 반영 | 수 초 |
| 문제 생성 (지문 2개 × 3문항) | 약 20~30초 |

녹화할 때는 기출 분석을 미리 한 번 돌려 두고, 화면에서는 결과부터 보여주면 대기 시간을 줄일 수 있습니다.

## 3. 데이터 초기화

데모 데이터는 원장 계정(`demo`)이 없을 때만 만들어지므로, DB를 비우고 다시 실행하면 처음 상태로 돌아갑니다.

- H2 (`h2,demo`): 서버를 끄고 `storage/h2` 폴더를 지운 뒤 다시 실행
- PostgreSQL (`demo`): 서버를 끄고 DB를 다시 만든 뒤 실행

  ```bash
  psql -U postgres -c "DROP DATABASE swmvp;" -c "CREATE DATABASE swmvp;"
  ```

- 업로드 파일(기출 PDF, 로고)은 `storage/` 아래에 남습니다. 깨끗하게 하려면 `storage/past-exams`, `storage/materials`, `storage/logos`도 지웁니다.
