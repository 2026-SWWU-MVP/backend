# 기출 PDF 추출 실험 결과 (이슈 #5)

- 날짜: 2026-10-01
- 모델: `gpt-5.6-terra` (OpenAI Responses API, json_schema strict)
- 대상: 실제 학교 기출 3개 (원본 PDF는 저작권 때문에 레포에 없음)

| 시험지 | 형태 | 페이지 | 특징 |
|---|---|---|---|
| 건대부고 1학년 1학기 기말 | 사진 → PDF (스캔본) | 8 | 학생 필기 많음, 페이지 가장자리 잘림 |
| 압구정고 고1 2학기 중간 | HWP → PDF (텍스트 있음) | 13 | 2단, ⓐ~ⓔ 문장 밑줄, (A)(B) 연결 지문 |
| 현대고 2학년 1학기 중간 | 사진 → PDF (스캔본) | 8 | 듣기 문항, 마지막 페이지에 정답표·모범답안 |

## 최종 결과 (v2)

| 시험지 | 문항 수 (원본) | 추출 | 코드 점검 이슈 | 토큰 | 시간 |
|---|---|---|---|---|---|
| 건대부고 | 선택 34 + 서답 6 | 34 + 6 ✅ | 3 (모두 실제 문제 위치) | 33,145 | 94s |
| 압구정고 | 객관식 24 + 서답 8 | 24 + 8 ✅ | 0 | 55,513 | 87s |
| 현대고 | 선택 26 + 서답 3 | 26 + 3 ✅ | 0 | 31,069 | 69s |

- **문항 수는 세 시험지 모두 원본과 정확히 일치**
- 스캔본에서도 인쇄된 밑줄을 대괄호로 정확히 변환 (예: 현대고 8번 `①[forbidding]` ~ `⑤[offend]`)
- 학생 필기(동그라미, 직접 쓴 답, O/X)는 answer에 들어가지 않음 (건대부고 40문항 모두 null)
- 인쇄된 정답표가 있으면 문항별로 정답을 연결 (현대고 29문항 모두, 복수 정답 `①②⑤`, 서답형 허용 답안까지)
- 남은 점검 이슈 3개는 실제로 사람이 봐야 하는 곳: 학생 필기 동그라미가 ① 밑줄을 가림(7번, 27번), 스캔 시 페이지 가장자리가 잘림(27번)

## v1 → v2에서 고친 것

| 발견 (v1) | 원인 | 조치 (v2) |
|---|---|---|
| 텍스트 PDF(압구정고)에서 밑줄이 사라지거나 추정됨. 모델 경고: "페이지 이미지가 제공되지 않아 밑줄은 추정" | 텍스트가 있는 PDF는 OpenAI가 텍스트만 모델에 전달 | **모든 페이지를 150dpi JPEG로 렌더링해 `input_image`(detail=high)로 함께 전송**. 텍스트 PDF는 철자 정확도를 위해 PDF 원본도 같이 보냄, 스캔본은 이미지만 |
| (A)(B)로 나뉜 지문 중 (B)가 아무 문항에도 연결 안 됨 | 문항이 지문을 하나만 참조할 수 있는 스키마 | `passageId` → **`passageIds` 배열** |
| [보기] 어구가 `"a / b / c"` 한 덩어리로 들어옴 | 모델 출력 편차 | 프롬프트 강화 + **코드에서 "/" 기준 분리** (서술형 배열·영작만) |
| 학생 필기가 정답으로 들어갈 위험 | 규칙 없음 | 프롬프트에 **손글씨 무시, 인쇄된 정답표만 answer** 규칙 추가 |
| 듣기 문항이 OBJ_OTHER로 분류 | 유형 없음 | `OBJ_LISTENING` 추가 (생성 대상 아님) |
| 점검 이슈 오탐 (선택지가 지문 안에 있는 문항, 문장 고르기형 어법, 어구가 본문·조건에 있는 배열) | 점검 규칙이 좁음 | `ExtractionChecker` 규칙 보완, v2 결과 재점검 시 오탐 0 |
| 큰 요청(이미지 수 MB)에서 `Connection reset`, 재시도도 2초 만에 실패 | JDK HttpClient HTTP/2로 큰 요청 전송 시 연결 끊김 + 끊긴 연결 재사용 | **HTTP/1.1 고정**, 네트워크 오류는 최대 3회 시도 + 대기 시간 증가 |

## 결론과 서비스 반영 사항

1. **멀티모달 추출 방식은 MVP에 사용 가능.** 스캔본(학생이 찍어 보내는 사진)도 문항 구조와 밑줄을 정확히 읽음.
2. **페이지 이미지 전송은 필수.** 텍스트 PDF만 보내면 밑줄 정보가 사라짐.
3. **사람 검수는 여전히 필요.** 필기로 가려진 밑줄, 잘린 페이지 등은 모델도 못 읽음. `ExtractionChecker` 이슈와 모델 `warnings`를 검수 화면에서 해당 문항 옆에 표시하면 강사가 어디를 봐야 하는지 바로 알 수 있음 (#8에 반영).
4. **응답 시간 70~95초.** 업로드 API에서 동기로 기다리면 안 되고, 추출도 문제 생성처럼 비동기 작업으로 처리해야 함 (#8에 반영).
5. 서답형 번호가 객관식 번호와 겹치는 시험지가 많음 → 문항 식별은 `(section, no)` 조합으로.
