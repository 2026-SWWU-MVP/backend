# 강사 검수 기록 반영 실험 (#42)

실행: `EXPERIMENT_FILTER=압구정 ./gradlew llmTest --tests '*TeacherReviewExperiment'` (2026-10-07, gpt-5.6-terra)

같은 지문 5개(압구정고 기출의 긴 지문)로 어구 배열을 **검수 기록 없이 / 있이** 만들어 비교했습니다. 프롬프트에 넣은 검수 기록(TeacherPreferences 형식):

- 폐기 (사유: [보기] 조각이 한두 단어씩 너무 잘게 나뉘어 너무 쉬움. 의미 단위로 크게 나눌 것)
- 수정: 해설 (긴 3문장) → (한 줄 요약) × 2건

## 결과

|---|---|---|---|---|---|

| 2차 — 기록 있음 | 5 | 6.0 | 3.7 | **130 (−32%)** | 5 |

## 해석

- 1차에서는 효과가 약했습니다. 시스템 프롬프트의 고정 규칙("해설 2~3문장")이 검수 기록보다 우선했기 때문입니다. 검수 기록의 우선순위를 "강사 정보 다음, 학교 기출 규칙보다 위"로 올리고 해설 규칙에 예외를 두자 **해설을 짧게 고친 방향이 바로 반영**되었습니다.
- 조각 크기(조각당 단어)는 바뀌지 않았습니다. 조각 수는 유형별 규칙(5~9개)과 고른 문장의 길이에 더 크게 좌우됩니다. 조각 크기를 강사 취향대로 바꾸려면 옵션(예: 조각 수 범위)으로 직접 받는 편이 확실합니다.
- 문항 수가 적고(5개) 같은 조건에서도 기준값이 흔들리므로(해설 174 → 191자) 초기 확인 수준입니다. 실제 사용 데이터는 `GET /api/workspaces/{id}/review-stats`의 생성 작업별 채택률로 봅니다.
