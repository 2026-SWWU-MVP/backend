# 전체 흐름 점검 + 발표용 수치 (이슈 #23)

실행: `./gradlew llmTest --tests '*EndToEndExperiment'` (2026-10-04, 모델 gpt-5.6-terra)

- 기출: 압구정고 고1 2학기 중간고사 (텍스트 PDF, 32문항)
- 시험범위: 같은 시험지 PDF → 지문 23개로 분리, 90단어 이상 긴 지문 16개 사용
- 강사 의견: "학생들 말로는 이번 서술형은 어구 배열 위주로 낸다고 하심"
- 지문당 유형 구성: v1 요약문 빈칸 2 · 어구 배열 1 → 의견 반영 후 확정 요약문 빈칸 1 · 어구 배열 2
- 생성: 16지문 × 3 = 48문항

API를 실제 순서대로 호출했습니다 (업로드 → 추출 → 프로필 → 강사 의견 → 확정 → 지문 분리 → 생성 작업 폴링). 검수 화면과 PDF 출력은 플랫폼 트랙 기능이 아직 없어 이번 점검에서 빠졌습니다.

## 발표용 수치

| 수치 | 결과 |
|---|---|
| ① 규칙 검증 통과율 | **100%** (48/48), 바로 쓸 수 있는 PASSED 98% (47/48), 확인 필요 1 |
| ② 검증 적용 전 vs 후 | 첫 시도의 **21%** (10/48)에서 정답 애매·오류 발견 → 재생성 → 강사에게 '통과'로 가는 문항 중 사람이 찾은 정답 오류 **(검수 후 기입)** / 47 |
| ③ 유형 구성 일치도 | **100%** (48/48), 강사 의견으로 바뀐 구성 그대로 |

재생성 이유 (실패한 시도 기준):

- 정답이 하나로 정해지지 않을 수 있다 (블라인드 풀이): 10회
- 정답 없이 푼 AI의 답이 정답과 다르다 (블라인드 풀이): 2회
- 빈칸 정답이 핵심 내용어가 아니다 (규칙): 1회
- 어구 배열 조각 중복 (규칙): 1회

→ 걸러낸 오류 대부분이 코드 규칙으로는 못 잡는 "복수 정답"이었고, 블라인드 풀이 검증이 이를 잡았습니다.

## 점검에서 발견해 고친 문제

첫 실행에서 지문당 어구 배열 2문항 중 **16쌍 중 8쌍이 같은 문장**으로 나왔습니다 (규칙 검증은 모두 통과). 문항을 서로 독립적으로 만들어 LLM이 같은 "좋은 문장"을 반복해서 고른 것입니다.

- 같은 지문·같은 유형 문항을 한 묶음으로 차례로 만들고, 앞 문항의 정답을 프롬프트에 넣어 다른 문장을 고르게 함
- 그래도 겹치면 `DISTINCT_FROM_EXISTING` 규칙 검증 실패로 재생성
- 개별 재생성도 같은 작업의 형제 문항과 겹치지 않게 함

수정 후 재실행: 중복 **0쌍**.
